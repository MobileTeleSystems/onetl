# 0.17.0 (2026-08-18) { #DBR-onetl-changelog-0-17-0 }

## Breaking Changes { #DBR-onetl-changelog-0-17-0-breaking-changes }

- Drop support for Python 3.7 - 3.9. Minimal Python version is now 3.10. ([#505](https://github.com/MTSWebServices/onetl/issues/505))
- Drop support for Pydantic 1.x, minimal required version now is 2.x. ([#531](https://github.com/MTSWebServices/onetl/issues/531))

- Directory paths passed to `FileDownloader`, `FileUploader` and `FileMover` cannot contain `..` and `~`. ([#529](https://github.com/MTSWebServices/onetl/issues/529))

- Avoid using classes dropped from `etl-entities==3.0.0`. ([#529](https://github.com/MTSWebServices/onetl/issues/529))

    Now `with etl_entities.process.Process(...)` context manager have no effect on onETL.
    This may change HWM name generated by deprecated `DBReader(hwm_column=...)` and `FileDownloader(hwm_type="file_list")`.

- Include DB/filesystem type into `Connection.instance_name` for following classes:

    * `Kafka.instance_url`: `some-cluster` -> `kafka://some-cluster` ([#539](https://github.com/MTSWebServices/onetl/issues/539))
    * `Hive.instance_url`: `some-cluster` -> `hive://some-cluster` ([#540](https://github.com/MTSWebServices/onetl/issues/540))
    * `HDFS.instance_url`: `some-cluster` -> `hdfs://some-cluster` ([#540](https://github.com/MTSWebServices/onetl/issues/540))
    * `SparkHDFS.instance_url`: `some-cluster` -> `hdfs://some-cluster` ([#540](https://github.com/MTSWebServices/onetl/issues/540))

    This may change HWM name generated by deprecated `DBReader(hwm_column=...)` and `FileDownloader(hwm_type="file_list")`.

## Features { #DBR-onetl-changelog-0-17-0-features }

- Ensure compatibility with Spark 4.2.x ([#522](https://github.com/MTSWebServices/onetl/issues/522))
- Add OAuth2 Client Credentials authentication for Kafka connections on Spark 3.4 and higher. ([#530](https://github.com/MTSWebServices/onetl/issues/530))
- Add `YAMLHWMStore(keep_history=True)` flag. ([#542](https://github.com/MTSWebServices/onetl/issues/542))
- Log duration of `.fetch()`, `.execute()` and `.sql()` methods of DB connection classes.
- Log duration of `.run()`, `.view_files()` and `.has_data()` methods.
- Now HDFS client uses `overwrite=True` during file upload, to mitigate configured retries.

## Improvements { #DBR-onetl-changelog-0-17-0-improvements }

- Add `reWriteBatchedInserts=true` to `Postgres(extra={...})` by default. This improves write performance, up to x2.
- Now `Connector.get_packages(spark_version=...)` arguments are detected automatically using installed `pyspark` version. Except `Excel` package.
- Make `Kafka(cluster=...)` parameter optional. ([#539](https://github.com/MTSWebServices/onetl/issues/539))
- Make `SparkHDFS(cluster=...)` parameter optional. ([#540](https://github.com/MTSWebServices/onetl/issues/540))
- Improve `Kafka.KerberosAuth` defaults. ([#541](https://github.com/MTSWebServices/onetl/issues/541))

    Passing `Kafka.KerberosAuth(principal=...)` without `keytab=...` will use Kerberos Ticket cache (filled up by `kinit`).

- Avoid calling `df.count()` in `JDBC.fetch()` and `JDBC.execute()` methods.

    Previously this lead to sending in-memory DataFrame from Spark driver to Spark executors to calculate rows count,
    even it was already known by driver.
